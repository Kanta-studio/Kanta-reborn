## Continuous execution and next-task ownership

Within an active engineering session, completing a task is a transition to the next highest-priority unblocked task, not a stopping point. After each change, inspect the current repository and CI state, choose the next actionable item from architecture, backlog, failing checks and release gates, and execute it without requesting another prompt. Prioritize reproducible regressions, iPhone/iPad runtime acceptance, parity gaps, and release evidence according to risk and dependencies. Diagnose failing job steps and logs before changing code; make the smallest architectural fix, update regression tests and the failure/repair ledger, then validate against the actual commit. Avoid redundant workflow dispatches and never confuse a green compile with UI acceptance, a signed IPA, or a verified download.

Maintain a durable handoff in docs: completed work with commit and run links, observed failures and root causes, current blockers, next executable task, and validation evidence. Keep architecture and task inventories synchronized with implementation; placeholders are not completed features. When a gate is unavailable, record the precise reason and immediately advance another independent task. Do not wait idly for CI when unrelated implementation can proceed safely. Only pause for an external dependency, authorization required by platform policy, or exhaustion of currently executable work. Never claim autonomous background execution after the active session ends; use an explicitly configured scheduled task for future monitoring.
